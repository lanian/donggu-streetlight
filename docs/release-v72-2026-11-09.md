# v72 시설 방문계획 차량 노선 공개

`v72-vehicle-routes`는 로컬 구현 `685bc60`의 차량 노선을 공개 앱에 반영한다. **관리 현황 → 미점검·방문 계획 → 차량 이동 노선 만들기**에서 남은 시설 전체를 기존 방문 순서대로 최대 6곳씩 구간화한다.

## 동작

- 한 시설만 남아도 차량 경로를 만들고 최대 200곳까지 누락 없이 나눈다. 두 번째 구간부터 이전 구간의 마지막 시설에서 이어진다.
- 첫 출발 위치가 없으면 네이버 지도앱의 현재 위치를 사용한다. **내 위치 확인** 후 카카오맵 웹·앱도 선택한다. 카카오의 출발점을 첫 시설로 임의 대체하지 않는다.
- ±100m 이내의 새 위치를 해당 차량 화면에서만 사용하고 5분 뒤 다시 확인한다. 위치 권한 거부·오류·저정확도일 때 네이버 지도앱의 현재 위치 경로를 이용할 수 있다.
- 외부 지도 선택이나 GPS 응답 중 계획·시설 좌표·완료 상태·계정·화면이 바뀌면 이전 결과를 적용하지 않는다. 경로 열기는 기존 방문 완료·점검 결과·계획 저장을 변경하지 않는다.
- 실제 도로 경로와 운전 시간은 외부 지도에서 확인한다. 앱의 계획 지도·방문 순서·거리는 직선 기준을 유지한다.

추가 API 키·경로 서버 요청·새 인증을 도입하지 않는다. 설치된 네이버·카카오 앱의 차량 경로 또는 카카오 웹 지도를 사용한다. Firebase·지도·주민 신고 설정, Firestore 규칙·Functions는 변경하지 않는다. 접수대장 실제 조회와 운영 반입 차단을 유지하며 기본 폴더의 별도 v61 개발분은 보존한다.

## 검증 범위

기능 본체는 로컬 구현과 같고 공개 버전·설명·서비스워커 캐시를 갱신한다. 신규 코어 22개, 차량 브라우저 18개, 기존 방문계획·업무·버전 회귀를 재확인하고 앱·서버/규칙·브라우저 48개 스크립트·Pages 배포 파이프라인을 확인한다. 배포 성공 후 공개 자산을 커밋 Git blob과 비교하고, 격리 브라우저에서 전체 구간·차량 URL·현재 위치 조건·오래된 결과 차단·기존 기록 유지와 모바일/PC 화면을 확인한다.

브라우저 검사는 Firebase 설정 null·로컬 시험 저장소·합성 GPS·외부 열기 stub을 사용하며 실제 지도앱 실행·도로 결과·실제 GPS·실운영 신고 조회·운영 Firebase 저장을 검증하지 않는다. 앱 설치와 기기별 실제 지도 전환은 현장 확인 범위다.
