# 화면 이동과 뒤로가기 규칙

앱의 상세 화면은 한 장의 시트(`#sheet`)에 그려지지만, 내부에서는 **화면 스택**으로 관리합니다. 스택의 한 단계가 브라우저 History의 한 항목과 1:1로 대응하고, History에는 깊이(`{nav: n}`)만 들어갑니다. 화면 HTML·입력 내용·사진·연락처는 History에 넣지 않습니다.

## 사용자가 체감하는 동작

| 조작 | 결과 |
|---|---|
| 휴대폰·브라우저 뒤로가기 | 사진 보기·사진 확인 패널·사진 편집기가 떠 있으면 **그 오버레이만** 닫힘. 아니면 **직전 화면 한 단계**로 복귀 |
| 화면 왼쪽 위 ‹ (접근성 이름 "뒤로", 맨 아래 단계에서는 "닫기") | 뒤로가기와 같음 |
| Escape, 배경 탭 | 뒤로가기와 같음 |
| 전체 닫기 | 별도 동작(`closeSheet("all")`). 화면 버튼에는 쓰지 않고 검사·복구 코드가 사용 |
| 같은 종류의 다른 항목 열기 (후보 이전/다음, 지도 200곳 페이지, 다른 시설·작업·자재) | 현재 단계를 **대체**. History가 늘지 않아 뒤로가기 한 번에 부모로 돌아감 |
| 저장 완료 후 자동 닫힘 | 부모 화면(목록)으로 한 단계 복귀 |
| 앱 루트(탭 화면)에서 뒤로가기 | 앱을 나감. 시트를 열 때만 History를 쌓으므로 앱 안에 갇히지 않음 |
| 새로고침·직접 진입 | 깊이 0에서 시작. 이전 문서의 깊이 값이 남아 있어도 `{nav:0}`으로 바로잡음 |

지원하는 대표 경로:

- 관리 현황 → 보수 작업 목록 → 작업 상세 → 시설 점검 → 사진 → (뒤로) 시설 점검 → 작업 상세 → 보수 목록(스크롤 유지) → 관리 현황
- 관리 현황 → 밝기 검토 목록 → 후보 지도 → 제외 구역 편집 → (뒤로) 후보 지도 → 목록(선택 후보·필터·스크롤 유지) → 관리 현황
- 신고함 → 신고를 보수 작업에 연결 → 기존 작업 선택 → 작업 상세 → (뒤로) 한 단계씩

## 구현

`index.html`의 "navigation" 블록이 전부입니다.

- `navRoute(key, reopen, {back, replace, push})` — 시트를 여는 함수가 `openSheet` 직전에 호출해 "이 화면을 다시 그리는 방법"을 등록합니다. `key`는 `종류:식별자` 꼴이고 같은 종류끼리는 대체됩니다. `back`은 이 화면에서 뒤로갈 때 부모를 그릴 특별한 방법(예: 밝기 지도 → `returnLightingReview`). 모듈은 `api.navigate(html, {key, reopen})`으로 같은 정보를 넘깁니다.
- `openSheet(html)` — 등록된 route에 따라 push(새 단계 + `history.pushState`) / replace(같은 단계) / restore(뒤로가기로 돌아온 단계 재그리기, History 변경 없음) 중 하나로 동작합니다. 덮이는 화면의 스크롤 위치를 저장하고, 카메라·센서·지도·패널을 먼저 해제합니다(`sheetLeave`).
- `closeSheet(mode)` — 인수 없음: 한 단계 뒤로(`history.back()`이 실제 pop을 수행). `true`: 지금 이 단계를 떠나되 다음 `openSheet`가 그 자리를 차지(닫고 바로 다른 화면을 여는 옛 호출부). `"all"`: 전부 닫기. `{pop:true}`: 내부용 정리.
- `popstate` → `navSyncTo(depth)` — 도착한 항목의 깊이까지 pop하고 새 최상단을 `reopen()`(또는 pop된 화면의 `back()`)으로 다시 그립니다. 재그리기가 아무것도 열지 않으면(삭제된 시설, 권한 없음) 그 단계도 버리고 한 번 더 뒤로 갑니다. 앞으로가기로 만들 수 없는 깊이가 오면 `history.go`로 맞춥니다.
- 늦은 응답 차단 — `navGen()`/`navAlive(g)`. 조회를 시작할 때 세대를 받아 두고, 화면을 바꾸기 직전마다 확인합니다. 세대는 새 화면을 열 때, 뒤로가기로 pop될 때, 오버레이를 닫을 때 올라갑니다. 사용자가 직접 `closeSheet()`한 직후 다른 화면을 열면 떠나던 단계를 그 화면이 대체하고, 뒤늦게 도착하는 `popstate`는 흡수합니다.
- 오버레이(`#ovl`, `#cmpSheet`, 사진 편집기)는 History 항목을 쓰지 않습니다. 뒤로가기가 오면 오버레이만 닫고 현재 깊이를 다시 push합니다.

## 화면 상태 복원 (NAV-03)

덮이는 화면은 덮이기 직전에 `navCapture`로 스크롤·입력 필드(`DGIntegration.captureForm`)·사진 미리보기·마지막으로 누른 컨트롤·지도 중심/확대를 자기 항목에 저장하고, 돌아올 때 `navRestoreState`로 되돌립니다. 목록 필터·페이지·선택 후보처럼 모듈 상태(`DGOperations.state`, `S.review`, `S.rv*`, `IB`)에 있는 값은 재그리기만으로 복원됩니다. 마지막으로 누른 행은 포커스를 받고 화면 밖이면 가운데로 스크롤됩니다. 지도(`openMap`, 밝기 후보 지도)는 `NAV.mapView`로 떠날 때의 중심·확대를 그대로 씁니다. 계산 결과가 낡은 경우(검토 무효화)는 결과를 재사용하지 않고 목록 단계로 돌아가 재실행을 안내합니다.

## 입력 보호 (NAV-04)

현장 등록(`asec:reg`)·신고 접수(`asec:inbox`)·등 정보 수정(`ledit:*`) 양식은 `FD`(form drafts)로 보호됩니다.

- 덮인 뒤 돌아오면(스캔·지도 등) 메모리에서 그대로 복원됩니다. 파일 입력에 파일을 다시 넣지 않고 사진 미리보기·첨부 상태(`__nPhoto`)만 되돌립니다.
- 저장소가 **영속**(`DGOffline.durable`, 로컬 체험 또는 신뢰 기기)이면 입력 0.4초 뒤 `formDraft:<양식>@<탭>` 키로 기기에 보관하고, 다음에 열 때와 새로고침 뒤 복원하며 "작성 중이던 … 불러왔어요 · 입력 비우기" 안내를 붙입니다. 키에 계정 네임스페이스와 브라우저 탭 ID가 들어가 탭·계정 사이에 섞이지 않습니다. 저장이 성공했을 때만(등록·접수·수정 저장) 초안을 지웁니다.
- 보관에 실패하면(용량 부족 등) 저장됐다고 표시하지 않고, 화면을 떠날 때 "입력을 이 기기에 보관하지 못했어요 — [확인] 입력을 버리고 이동 · [취소] 머무르기"를 묻습니다. **공유 기기 모드**(비영속)에서는 아무것도 쓰지 않고 떠날 때 같은 선택을 묻습니다.
- 이 질문은 ×·Escape·배경 탭(`closeSheet`)과 휴대폰 뒤로가기(`popstate`) 모두에 적용됩니다. 뒤로가기는 취소할 수 없으므로 "머무르기"를 고르면 깊이를 다시 push해 화면을 유지합니다. 새로고침·종료 직전 경고(`beforeunload`)는 보관되지 않은 입력이 있을 때만 뜹니다.
- 점검·보수·순찰·밝기 관찰·제외 구역·재확인 업무는 각자의 기존 초안 체계를 그대로 씁니다.

## 탭·앞으로가기·새로고침 (NAV-06)

- **탭 전환도 이력**입니다. 시트가 닫힌 상태에서 탭을 바꾸면 `{nav:0, tab}` 항목이 하나 쌓이고(같은 탭 반복 클릭은 쌓지 않음), 뒤로가기는 이전 탭으로, 첫 항목에서는 앱 밖으로 나갑니다. 시트의 모든 항목이 열렸던 탭을 함께 기록하므로 시트를 닫아도 그 탭에 남습니다.
- **앞으로가기**는 뒤로가기로 떠난 화면을 메모리(`NAV.forward`)에서 다시 엽니다. 저장 요청·신고·보수 작업은 다시 실행되지 않고 `reopen()`으로 그리기만 합니다. 새 화면을 열거나 탭을 바꾸면 앞으로가기 목록은 비워지고, 새로고침 뒤처럼 만들 수 없는 깊이로 가면 `history.go`로 현재 깊이에 맞춥니다.
- **빠른 연속 뒤로·앞으로**는 `popstate`마다 순서대로 동기 처리되고(`NAV.syncing`), 비동기 재그리기는 세대 번호로 늦은 완료를 버립니다. 스택 깊이와 `history.state.nav`는 항상 같습니다.
- **권한 변경**: 화면을 다시 그릴 때마다(`render` → `navRevalidate`) 맨 위 화면이 더 볼 수 없는 화면이면 닫고 안내합니다. 권한이 없는 섹션은 열리지 않습니다.
- **삭제된 시설·없는 항목**: 복원 route가 아무것도 열지 않으면 그 단계를 버리고 한 번 더 뒤로 가서 부모 화면에 안착합니다.
- **새로고침·직접 진입**: 깊이 0에서 시작하되 항목의 탭 값은 남겨 뒤로·앞으로가 탭을 일관되게 복원합니다.

## 검사

`node scripts/navigation-browser-smoke.cjs`, `node scripts/navigation-state-browser-smoke.cjs`, `node scripts/navigation-history-browser-smoke.cjs` (CI의 Local browser workflows에 포함). 작업 상세→시설→사진의 단계별 복귀와 스크롤 유지, Escape·‹의 한 단계 동작, 같은 종류 화면의 대체, 늦은 이력서·사진 응답 차단과 늦은 오류 안내 억제, 신고 연결→작업 상세 복귀, 오버레이 단독 닫기, 연속 뒤로가기와 새로고침 뒤 깊이, 밝기 지도→제외 구역 편집→지도→목록.

기존 검사 중 "닫으면 전체가 닫힌다"를 전제했던 부분(`sheet-transitions`, `lighting-review-navigation`, 각 smoke의 `close` 헬퍼)은 한 단계 복귀 규칙에 맞춰 바꾸고 주석으로 이유를 남겼습니다.

## 실기기 미검증 · 점검표

삼성 Android Chrome과 설치형 PWA의 뒤로 버튼·제스처는 데스크톱 Chromium 모바일 뷰포트에서만 확인했습니다. 현장에서 다음을 한 번씩 눌러 보세요.

1. 관리 현황 → 보수 작업 → 작업 하나 → "시설 점검 열기" → 사진 하나 크게 보기 → 뒤로 4번: 사진만 닫힘 → 시설 → 작업 → 목록(같은 위치) → 관리 현황.
2. 밝기 검토 → 후보 지도 → 다음 후보 3번 → 뒤로 1번: 목록으로 바로.
3. 시설 상세에서 Escape 대신 왼쪽 위 ‹: 한 단계만.
4. 앱 첫 화면에서 뒤로: 앱이 닫히거나 이전 사이트로 나감(갇히지 않음).
5. 설치형 앱에서 1을 반복.

## 남은 과제

- 실기기(삼성 Android Chrome·설치형 PWA) 점검표 수행 결과 반영.
- 공유 기기 모드의 초안을 세션 종료 시 명시적으로 지우는 옵션(현재는 메모리에만 있어 창을 닫으면 사라짐).


## 모바일 하단 메뉴 배치 (v23-bottom-navigation)

- 실제 공개 앱은 `FEATURES.reports=false`로 주민 신고가 별도 `report/` 페이지에 분리되어 있습니다. 하단에는 **현장 점검 / 관리 현황** 두 메뉴가 보이며, 메뉴를 세 열로 고정하지 않고 *현재 표시되는 메뉴의 수만큼* 균등 배치합니다. 추후 세 메뉴가 모두 허용돼도 동일한 원칙입니다.
- 선택된 메뉴는 은은한 배경·상단 표시선·아이콘 색으로 구분합니다. 다크 모드·강제 고대비 모드와 키보드 초점 표시를 지원합니다.
- 항목은 최소 44×44px보다 크게 유지하고, 320px 이하 소형 화면에서도 서로 겹치지 않도록 조정합니다. iOS/Android의 `safe-area-inset-bottom`만큼 하단을 비워 버튼을 제스처 영역 위에 둡니다. 콘텐츠 하단과 토스트 메시지도 이 영역을 고려합니다.
- `ArrowLeft`/`ArrowRight`, `Home`, `End` 키는 현재 보이는 항목만 순회합니다. 실제 선택은 기존 클릭 흐름과 같은 `navTabSwitch`를 사용하므로 뒤로가기 기록이 별도로 달라지지 않습니다. `tabindex`는 선택된 항목 하나에만 0을 지정합니다.
- 권한상 표시할 하단 메뉴가 하나 이하이면 내비게이션을 숨기고 불필요한 본문 하단 여백을 줄입니다. 주민 신고 별도 페이지의 접수 절차와 저장 권한은 변경하지 않습니다.
- 검증: `node scripts/bottom-nav-browser-smoke.cjs`. CI `Local browser workflows`에 포함됩니다. 320/360/390/768px, 2개/3개/0개 노출, 터치 선택·History 뒤로가기, 키보드, 제스처 영역 여백을 검사합니다. 실제 단말 제스처 조작은 별도 확인이 필요합니다.
