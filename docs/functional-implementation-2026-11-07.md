# 기능 오류 수정과 업무 기능 추가 · v60

현재 로컬 개발 버전은 `v60-workflows`다. [수정 전 전체 검토](functional-review-2026-11-07.md)에 대한 사용자의 구현 요청을 반영했다. Firebase 연결 설정과 주민 접수 설정은 유지했고 운영 자료 변경·커밋·푸시·배포는 하지 않았다. 기존 v59 배포 후보 ZIP은 당시 결과로 보관하며, 이번 v60 구현을 담은 파일은 아니다.

## 수정한 오류

| 검토 항목 | 반영한 동작 |
|---|---|
| F-01 점등 확인이 고장·재점검 해제 | 직접 점등 확인은 종합 상태·재점검 사유·정식 점검 날짜를 바꾸지 않는다. 고장 관찰은 상태의 심각도를 높일 수 있다. 이전 버전의 저장 대기 순찰도 전송할 때 안전한 패치를 재구성한다. |
| F-02 이전 GPS 좌표에 새 관찰 저장 | 좌표·정확도·수신 시각을 함께 관리한다. 거절된 위치나 오래된 위치로 어두운 지점을 기록하지 않는다. |
| F-03 복구 후 취소 대상 오류 | 관찰·어두운 지점의 순서를 직렬화해 복구하고, 마지막 행동을 되돌린다. |
| F-04 순찰 진행률 66% 한계 | 정확한 좌표를 가진 실제 통과 대상을 같은 분자·분모 기준으로 계산한다. 과거 기록도 현행 대상 기준으로 집계한다. |
| F-05 연결된 신고에서 실패할 새 작업 작성 | 기존 진행 작업 열기를 제공하고 불가능한 작성 경로를 미리 막는다. 작성 중 다른 직원이 연결한 경우 입력을 유지하고 잠금을 해제한다. |
| F-06 거꾸로 된 보고서 기간 허용 | 조회·인쇄·CSV가 같은 기간 검증을 사용한다. 입력을 정정하면 다시 조회할 수 있고 종료일 마지막 밀리초도 포함한다. |

순찰 상태 반영은 로컬 조건부 커밋과 Firebase 트랜잭션에서 최신 시설을 확인한다. 더 최근의 보수 결과가 저장 중에 들어와도 과거 순찰 관찰로 되돌리지 않는다. 재고 합계의 상한 초과도 저장 전에 거절한다.

## 추가한 기능과 사용 위치

1. **보수 작업 → 작업 상세 → 작업 정보 수정**: 상태를 유지하며 제목·내용·종류·우선순위·담당자·기한을 수정한다. 예정 자재는 검수 대기 전까지 수정할 수 있다. 검수 대기의 실제 자재 변경은 기존 보완 요청을 사용한다. 작업의 사진·신고 연결·이미 인정한 비용·재고 차감 이력은 보존한다.
2. **자재 재고 → 품목 → 기본정보 수정**: 자재명과 기준 단가를 사유와 함께 정정한다. 단위·현재 수량·과거 작업 단가는 유지하고, 수량 변동 없는 수정 이력을 남긴다. 초안은 해당 품목과 저장 대기함에서 복구·폐기할 수 있고, 입력을 원래 값으로 되돌리면 미저장 초안도 정리한다.
3. **현장 목록 → 추정 좌표 정비**: 동·분전함으로 확인 대상을 좁히고 현재 정확 좌표·추정 좌표 수와 조건별 남은 대상을 본다. 시설을 열면 기존 위치 보정 화면을 사용한다.
4. **자재 재고 → 예정 자재 소요·부족 예상**: 페이지로 나뉜 현재 작업 목록 대신 전체 미완료 작업을 조회한다. 저장된 자재와 이미 차감한 양의 차이를 합산하고 현재 재고·소요·사용 후 예상·부족량을 표시한다. 연결 작업과 미연결 자재의 작업을 열 수 있다. 조회 시각·자료 출처·조회 실패를 표시하며 새로고침으로 재조회한다. 이는 예약 재고가 아니며 실제 차감은 검수 승인 시점이다.
5. **방문 계획 → 이 계획으로 야간 순찰**: 미확인 시설을 순찰 목표로 보관한다. GPS 통과와 직접 관찰을 구분하고 종료 때 미확인 목표를 보여 준다. 미확인 목표는 버튼을 눌러 다음 순찰로 이월하고 저장 대기함에서 이어 열거나 폐기할 수 있다. 방문 계획의 점검 완료를 자동으로 대신하지 않는다.
6. **보수 작업 목록 → 행 선택 → 선택 작업 일괄 수정**: 담당자·기한·우선순위를 작업별 버전으로 변경한다. 담당자를 지정한 배정 대기 작업은 배정됨으로 바꾸어 담당자가 시작할 수 있게 한다. 다른 작업의 상태는 유지한다. 작업별 성공·대기·충돌을 표시하며 충돌한 선택은 남긴다.

## 초안과 동시 변경 보호

- 작업·자재 수정의 초안과 저장 작업은 계정·저장소 범위에 연결한다. 비동기 작업 중 계정이나 화면이 바뀌어도 다른 계정의 초안을 삭제하거나 새 편집 화면을 덮지 않는다.
- 공통 대기함의 항목 폐기와 완료 항목 자동 정리도 시작한 저장소 범위를 지킨다.
- 자재 정보가 바뀐 경우 기존 입력과 최신 정보를 확인한 뒤 명시적으로 새 버전에 적용한다. 전송 중인 명령의 내용을 초안 폐기로 바꾸지 않는다.
- 작업 수정 초안이 오래된 경우 이전 입력과 최신 내용을 비교해 표시한다. 사용자가 **이전 입력으로 이어 수정**을 선택해야 최신 버전 기준으로 재개한다. 비교 중 자료가 다시 바뀌면 재비교하며, 이전 초안은 전송 성공까지 보관한다.
- 재시도는 원래 명령 ID와 내용을 사용한다. 작업 수정과 자재 정보 수정의 불변 이력에는 내용 해시를 남긴다. 자재 수정 이력은 백업·복원 검증에서도 허용한다.

## 검증 범위

자동 회귀, 로컬 Chromium 업무 흐름, 로컬 Firebase 권한·서버·복원 에뮬레이터로 검증한다. 실제 현장 GPS·카메라·야간 OCR 정확도, 장시간 모바일 오프라인, 운영 계정 동시 사용은 이 결과에 포함하지 않는다. 최종 실행 결과는 아래에 기록한다.

- `node scripts/check.mjs`: **393개 통과**, 실패·건너뛰기 0. 원래 회귀 328개에 기능·경계·동시 변경 검사 65개를 추가했다.
- Node 22의 Functions 단위검사: **9개 통과**.
- 로컬 Firestore 권한 검사: **46개 통과**. 신규 배정·자재 수정 명령의 실제 트랜잭션·동일 명령 재시도도 포함한다.
- 로컬 서버 업무 **7개**, 운영 복원 **8개** 통과. 자재 수정의 새 불변 이력은 전체 백업 그래프 복원에서도 확인했다.
- 브라우저 **37종 모두 통과**. 신규 작업 8개 시나리오, 신규 자재 6개 시나리오, 신규 순찰·좌표 정비·목표 이월·보고서 수정 흐름을 포함한다. 각 검사에서 처리되지 않은 브라우저 오류는 0개다. 기존 탐색 검사의 전체 작업 수 가정은 실제 제출한 작업 ID를 확인하도록 보완했다.
- 전체 스크립트 구문·전역 이름 중복·필수 자산 확인과 `git diff --check` 통과. 앱과 서비스 워커 버전은 `v60-workflows`로 일치한다.
- `firebase-config.js`, `report/config.js`는 작업 전후 SHA-256이 일치한다. 권한 규칙과 복원 검증의 소스 수정은 로컬에만 있으며 운영 서버에 반영하지 않았다.

재현 로그는 `D:\Temp\streetlight-v60-final-check.log`, `D:\Temp\streetlight-functional-rules-final.log`, `D:\Temp\streetlight-functional-emulator-green.log`, `D:\Temp\streetlight-v60-final-browser\`에 있다. 임시 진단 및 브라우저 자료는 공개 앱 파일에 포함하지 않는다.
