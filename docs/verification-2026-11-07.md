# 2026-11-07 개선 및 검증 기록

기준 커밋: `7df7ea5`. 앱·서비스 워커 버전: `v59-reliability`. 변경은 로컬 작업 폴더에 있으며 운영 Firebase 데이터 변경·배포와 GitHub push는 수행하지 않았다.

## 변경

- 개인정보 파기는 미이관 `citizen_reports`와 이관 `reports`를 모두 조회한다. 개별 만료일과 현재 정책 중 이른 시각을 사용하고, 이전 대기 작업의 관리자·ID·기준 시각을 유지한다. 실제 실행은 트랜잭션 또는 조건부 저장으로 대상을 다시 확인한다. 지원하지 않는 저장소는 확인·조회·대기함 등록 전에 안내한다.
- 공개 Firestore 생성은 차단하고 기존 App Check·횟수 제한 게이트웨이만 서버 접수에 사용한다. 미설정 상태와 실패·충돌 응답은 접수 성공으로 표시하지 않는다. 같은 내용의 게이트웨이 재시도는 같은 요청 ID를 사용한다.
- localhost·loopback 실행은 체험 저장소를 사용하고 호스팅된 직원 Firebase 설정은 유지한다. 임시 전화번호를 제거하고 README·배포·보안·운영 안내를 실제 설정에 맞췄다.
- 직원·주민 진입 JavaScript와 CSS를 별도 파일로 분리했다. 직원 HTML은 539,936바이트에서 7,868바이트가 되었다. 기존 직원 CSS는 줄바꿈 정규화 후 원본과 동일하다. 분리한 진입 스크립트·CSS·개인정보 모듈을 서비스 워커에 포함하고, 검사기가 분리된 스크립트와 페이지 전체 전역 범위를 검사한다.
- 분전함 기준 추정 좌표는 방문 순서에서 제외하고 별도 안내한다. 개별 지도 열기에는 위치 한계를 안내한다. 이전 계획도 현재 시설 정보로 확인하며 방문 표시·작업 연결·순서를 보존한다. Firebase 초기 정보가 늦으면 전체 정류장 정보를 보관했다가 복구하고, 지도 선택 중 좌표가 바뀌면 이전 경로를 열지 않는다. 제외 시설만 있는 계획은 완료로 표시하지 않는다.

## 운영 반영 조건

주민 접수는 `report/config.js`의 게이트웨이 URL과 App Check가 준비되기 전까지 접수 준비 중으로 표시한다. 운영자는 Functions·비밀값·허용 origin·App Check·Firestore 규칙과 주민 설정을 함께 준비해야 한다. 변경된 규칙을 배포하면 구버전의 직접 접수 페이지도 차단되므로 게이트웨이를 준비한 전환 절차가 필요하다. Pages 게시만으로 Firebase 운영 설정이 반영되지는 않는다.

추정 좌표 2,826개는 원본 값을 유지한다. 실제 위치 보정은 현장 확인 후 기존 좌표 수정·승인 흐름으로 처리한다. `app/staff-app.js`는 기존 전역 UI 상태와의 호환 진입점이며, 이번 변경을 전체 ES 모듈 전환으로 해석하지 않는다.
