# v68 주민 신고를 운영서비스로 연결

`v68-official-report`는 주민 QR 페이지의 기본 동작을 실제 운영서비스 화면으로 이동하는 방식으로 바꾼다. 비공식 앱에서는 접수하지 않으며, 시설 선택·휴대폰 확인·사진·연락처 입력과 실제 접수는 운영서비스에서 마친다. [주민 신고 운영 안내](citizen-report-plan.md)를 참고한다.

## 구현

- 공개 서비스가 선언한 고장 신고 `/slamp/repair/map`과 처리현황 `/slamp/repair/status`로 이동한다. HTTPS 호스트·경로를 검증하고 시설번호·개인정보 쿼리, opener와 referrer를 전달하지 않는다.
- 선택 메모는 표찰·고장·설명만 복사한다. QR 시설 ID가 공개 대장의 유일한 활성 시설과 일치할 때만 실제 운영 시설번호를 넣는다. 오래된 표시번호를 정정하고 삭제·누락 ID를 같은 표찰의 다른 시설에 연결하지 않는다.
- 운영서비스 연결 모드에서는 사진·연락처·GPS·자체 접수와 상태 조회를 숨기고 실행도 차단한다. 이동·복사를 접수 완료로 표시하거나 접수번호를 만들지 않는다. 복사 실패 시 직접 복사할 수 있으며 입력은 유지한다.
- 별도 설정한 자체 게이트웨이·문자·이메일 흐름은 유지한다. 직원 화면의 주민 안내와 서비스워커의 버전·필수 자산도 함께 갱신한다.
- 주민 전달 방식이 바뀌어도 권한 있는 직원의 기존 자체 접수 조회·이관은 유지한다. 번호 수정 직후에는 보이는 입력값을 미확인 표찰 메모에 그대로 넣고 이전 시설 연결만 해제한다.

공식 자동 접수 API·시설 자동 선택·처리결과 동기화는 연결하지 않는다. 직원 Firebase·게이트웨이·App Check 값, Firestore 규칙과 Functions는 변경하지 않는다. 운영서비스로 실제 신고를 보내지 않는다.

## 검증 범위

공개 서비스의 리다이렉트·신고/조회 GET 응답과 배포된 클라이언트의 라우터를 확인했다. 실제 휴대폰 확인·접수·접수번호 발급은 검증하지 않았다.

신규 helper 단위 검증 13개, 표찰 수정 회귀 1개와 공식 신고 Chromium 시나리오 17개를 추가했다. 최초 누락 기능·모바일 textarea 경계·긴 QR 표찰 넘침·표찰 수정 메모 누락을 RED로 재현한 뒤 수정했다. 공식 URL 제한·QR 오연결 방지·복사 성공/거부·입력 유지·개인정보 및 자동 전송 차단·gateway/SMS 회귀를 외부 요청을 차단한 환경에서 확인한다. 390px·1280px 화면과 카드 내부 경계를 확인한다. 공개 배포 후보 Node 검증은 473개, v61 개발분을 보존한 기본 폴더는 561개를 통과했다. 전체 서버·규칙·브라우저 CI와 공개 배포 확인은 배포 기록에 남긴다.
