# Report Output v66 Implementation Plan

**Goal:** 기간 보고서·사진 대지·시설 이력·업무 현황을 누락 없이 읽기 좋은 A4 인쇄/PDF로 출력한다.

**Architecture:** 원래 화면·History·초안을 유지한 채 출력 사본을 만드는 `DongguPrint`를 공통으로 사용한다. 비동기 준비·글꼴·사진 처리 후 조회 조건·화면·계정을 재검증한다. 서식은 `app/print.css`로 분리하고 집계 의미와 원본 저장 형식은 유지한다.

**Tech Stack:** 기존 JavaScript·CSS·브라우저 인쇄, Playwright PDF, PyMuPDF 렌더 검증. 추가 서버나 유료 API는 없다.

---

1. 공통 출력 생명주기와 실제 보고서 데이터 회귀를 먼저 실패시킨다.
2. 공통 모듈에서 원화면 보존·중복 방지·실패/이탈/afterprint 정리·글꼴/사진 준비·제목 복원을 구현한다. 데이터가 담긴 버튼 내용은 보존한다.
3. 기간 보고서에 전체 점검/이상 발견 범위, 조회·현황 시점, 집계 기준을 명시한다. 현재 시설이 없는 동의 기간 기록도 동별 합계와 CSV에 포함한다.
4. 긴 메모는 표의 번호 참조와 전체 메모 부록으로 인쇄해 좁은 표 안에서 페이지가 과도하게 늘지 않도록 한다. 불량 항목의 상위 6종 제한을 제거한다.
5. 표 머리글 반복, 긴 문자열 줄바꿈, 사진 원본 비율, 조치 전후 묶음, 페이지 번호와 A4 여백을 적용한다. QR 실측 치수는 유지한다.
6. 동일 합성 자료의 기존 PDF(기간 13쪽/사진 4쪽/현황 3쪽)와 개선본을 렌더·텍스트·사진·페이지별로 비교한다. 빈 페이지·잘림·누락·표/사진 분리를 검사한다.
7. 코드·관련 브라우저·독립 검토와 전체 CI가 통과하면 v66으로 배포하고 공개 자산·출력 사본을 확인한다. v61 개발분과 서버 설정은 보존한다.

페이지 번호는 [Chrome 공식 인쇄 여백 상자 안내](https://developer.chrome.com/blog/print-margins)의 paged media counter를 사용한다. 실제 출력 결과로 재확인하며 브라우저 자체 머리글/바닥글 중복을 줄이는 안내를 제공한다.
