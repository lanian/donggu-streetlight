# 운영 신고 파일 반입 준비 구현 계획

**Goal:** 담당 부서 협의 전에 신고 반입의 공통 검토·중복 방지·시설 연결·실행 절차를 구현하고 합성 자료로 검증한다. 실서비스 접속·실제 자료 반입·공개 배포는 수행하지 않는다.

**Architecture:** 운영 API나 반출 양식을 추정하지 않고 명시한 연계 준비용 CSV/JSON을 사용한다. 순수 parser/plan과 로컬 전용 실행기를 분리하여 향후 승인된 파일/API 어댑터가 같은 검토 엔진을 사용할 수 있게 한다. 기존 QR 이관 함수와 저장 대기 큐는 사용하지 않는다.

**Tech Stack:** classic JS/UMD, 기존 DGData local atomic commit, 관리자 화면, Node·격리 Chromium.

## 1. 순수 입력·검토

- 새 `app/official-report-import-core.js`, `scripts/tests/official-report-import.test.cjs`.
- 준비 양식은 `external_report_id,lamp_id,issue,received_at,status`다. CSV는 UTF-8/BOM·인용부호·개행을, JSON은 버전 1 envelope/배열을 지원한다. 공식 업체의 양식이라고 표시하지 않는다.
- 2MiB·1,000건 제한을 적용하고 잘못된 날짜·식별자·필수값·중복 CSV 열은 거절한다. 원문을 오류에 출력하지 않는다.
- 이름·연락처·사진·GPS·위치 설명·자유 메모 등 추가 필드는 값이나 원본 키를 보관하지 않고 제외 개수만 남긴다. 메모·사진을 개인정보가 제거된 자료라고 오인하게 표시하지 않는다.
- 운영 시설번호 `lampId`의 유일한 활성 일치만 연결한다. 표찰·가까운 위치·p 접두어로 추정하지 않는다.
- 신규/기존 중복/파일 내 중복·충돌/미연결/중복 시설/종결을 구분한다. 기존 신고·완료 상태·작업은 덮지 않는다. 원본 종결·취소는 적용 대상에서 제외한다.

## 2. 로컬 전용 실행

- 새 `app/official-report-import-commands.js`.
- actor=`local`, DB mode=`local`, Firebase 없음, 관리자·쓰기 권한, 동일 화면·계정·DB·namespace가 모두 맞을 때만 실행한다. 운영 환경은 읽기 이전에 차단한다.
- 실행 직전 최신 신고와 시설로 다시 계획한다. 안정적인 출처별 신고 ID와 `commitMany`의 create-if-absent/expected 조건으로 한 번에 신규만 생성한다. 선택한 ID를 검증하고 재시도·다른 탭 충돌 때 기존 기록을 덮지 않는다.
- 기존 신고 스키마만 사용하며 `ext`를 다른 용도로 쓰지 않는다. 신규 상태는 `접수`이고 원본 처리 상태로 직원 업무를 자동 완료하지 않는다. 원본 상태는 생성한 설명에만 정해진 문구로 남긴다.
- 실서버 작업·DGOffline.submit·자동 로그인·운영 API 호출·백그라운드 재전송을 등록하지 않는다.

## 3. 관리자 화면

- 새 `app/official-report-import.js`·전용 CSS. `legacy-bridge.js`에 API·섹션을 연결하고 기존 운영 시스템 연계에서 진입한다.
- 준비 양식 내려받기·합성 예제·파일 선택 → 건수/신규·중복/시설 연결 검토 → 선택한 건을 체험 신고함에 적용한다.
- 실제 저장소 환경에서는 파일 검토·적용을 비활성화하고 협의 전 준비 기능임을 표시한다. 새 동작 때문에 기존 서버 자료를 읽지 않는다.
- 읽기·파일 교체·화면 이동·권한/DB/계정/namespace/시설 변경의 늦은 결과를 거부한다. 가져오는 중에는 조건·선택을 고정한다. 원본 파일과 원문을 초안·로그·기기 저장소에 보관하지 않는다.

## 4. 검증과 보존

- core/commands와 새 실제 Chromium의 미구현 RED → GREEN을 확인한다. 정상·CSV/JSON·개인정보 제외·중복·파일 충돌·유일 시설·종결·원본 보존·재실행·저장 실패·stale/권한/운영환경 차단을 검사한다.
- Node 전체·관련 브라우저·390/1280px 주간/야간 화면을 검증한다. 실서비스·실제 Firebase·외부 요청을 격리한다.
- `index.html`과 서비스워커에 새 필수 자산을 추가한다. 개발 버전은 `v70-import-prep`이며 공개 사이트의 v69는 유지한다.
- v69 기준 별도 `feature/official-report-import-prep` worktree에서 구현한다. 기본 폴더에는 최소 변경만 동기화하고 v61 개발분을 보존한다. 로컬 구현 기록만 남기며 push·Pages·Firebase 배포를 수행하지 않는다.

## 협의 후 남는 작업

담당 부서와 처리 근거·반출 항목·보관·권한·운영 업체의 공식 파일/API 계약을 확인한다. 그 계약에 맞는 어댑터·승인된 운영 실행기·규칙/감사·첨부 정책을 별도로 검증한 뒤 운영 연결과 배포를 진행한다. 현재 준비 구현이 해당 승인을 대신하지 않는다.
