# 접수대장 연결 준비 계획

**Goal:** 공식 명세를 받았을 때 기존 파일 반입 검토 엔진에 연결할 수 있도록 기간 조회·페이지 수신·명시적 항목 변환·완료 검증을 구현한다. 명세·허용 조회 경로가 없으므로 실제 접수대장 연결은 미완료 상태로 유지한다.

**확인한 제약:** 사용자가 아직 담당 부서 협의 자료가 없다고 답했다. 보호된 접수대장 조회·로그인·휴대폰 확인·보고서 증빙 흐름을 대체하지 않는다. 숨은 API 탐색·번들 역분석·실서비스 요청·비밀번호/쿠키 입력·실자료 수집·자동 배포를 하지 않는다.

**Architecture:** 네트워크 없는 주입형 페이지 수신기와 명시적 schema profile을 추가한다. 실제 endpoint/transport/provider profile은 만들지 않는다. 결과는 기존 `normalizeRows → plan → local-only execute`에 연결한다. UI의 실제 조회는 미연결로 고정하고 합성 2페이지 응답으로만 검증한다.

## 1. 순수 커넥터

- 새 `app/official-ledger-connector.js`, `scripts/tests/official-ledger-connector.test.cjs`.
- 조회 기간은 엄격한 KST 날짜 범위로 검증한다. 페이지 항목·전체 건수·다음 cursor·완료 flag·5개 업무 필드의 경로와 코드 매핑을 profile에 명시한다. 실제 업체 필드 이름이라고 표시하지 않는다.
- 임의 getter/prototype 경로를 읽지 않는다. 추가 원문 값·키는 결과에서 제거하고 제외 개수만 반환한다. 오류에 원문·URL·토큰을 포함하지 않는다.
- 모든 페이지 완료·동일 total·기간·최대 1,000건/50페이지·중복 ID·반복 cursor·빈 중간 페이지를 확인한다. 일부 결과를 완료처럼 반환하지 않는다.
- 취소·timeout·화면/계정 변경·늦은 응답·401/403 등을 합성 transport로 RED→GREEN 검증한다. `queryLive`는 연결 미설정 오류로 즉시 거절한다.

## 2. 기존 반입 화면 연결

- `app/official-report-import.js/css`에 **실운영 접수대장 연결** 카드를 추가한다. 날짜·미연결 상태·비활성 실제 조회 버튼·합성 연계 흐름 확인을 제공한다.
- 합성 응답이 모두 성공한 뒤에만 기존 미리보기를 만든다. 읽기 중 취소/화면 이탈은 AbortController와 sequence로 무효화하며 실패 때 부분 자료·이전 선택을 적용하지 않는다.
- 조회 기간을 바꾸면 조회에서 만든 미리보기만 무효화한다. 기존 파일 반입은 유지한다. 동작 중에는 기간·입력을 잠근다.
- 실제 저장소에서는 합성 조회/파일 검토/반입을 계속 차단한다. 기존 local-only 실행기·서버 큐 미사용·신규 생성만 허용하는 정책은 변경하지 않는다.

## 3. 검증·보존

- 새 실제 Chromium에서 미구현 UI RED를 먼저 확인한다. 기간·2페이지 결과·기존 체험 반입·오류/취소/늦은 응답/권한/운영 차단과 주야간 390/1280px을 검증한다.
- 기존 반입 15개·Node 전체·버전 회귀와 자산 구문 검사를 실행한다. 실제 target·Firebase·외부 요청은 사용하지 않는다.
- 새 자산을 HTML·SW에 등록하고 개발 버전 `v71-ledger-prep`로 구분한다. 공개 v70과 운영 설정·규칙·Functions를 유지한다.
- 별도 `feature/ledger-connector-prep` worktree에서 구현 후 기본 폴더에 최소 변경만 동기화한다. 기존 v61 WIP는 보존한다. 현재 작업은 실제 연계와 공개 배포를 완료한 것으로 표시하지 않는다.

## 실제 연결에 필요한 자료

담당 부서의 허용 범위와 공식 API/반출 문서 또는 승인된 비식별 예제가 필요하다. 인증 방식·접수 ID 범위·시간대·페이지 완료 판정·상태/변경/삭제 정책을 확인한 뒤 해당 계약의 입력 어댑터와 승인된 transport를 연결해야 한다. 임의 URL이나 내부 API를 추정해 이 단계를 대신하지 않는다.
