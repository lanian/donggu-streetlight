## 공개 앱 확인

워크플로의 최종 성공을 확인한 뒤 공개 앱 자산 11개와 시설 대장의 SHA-256을 공개 커밋 Git blob과 비교해 모두 일치했다. 새 브라우저 문맥 두 개에서 실제 읽은 UI 자산도 각각 10종 모두 일치했다. 서비스워커 실행은 차단하고 `sw.js`는 파일 해시로 확인했다.

Firebase 설정을 null로 대체한 뒤 local 계정·local DB·Firebase 연결 없음·v72를 먼저 확인하고 실제 공개 UI로 방문계획 화면을 열었다. 공개 대장에서 활성·정밀 좌표 시설 14곳을 골라 방문 완료 1곳과 미완료 13곳으로 된 합성 계획만 이 시험 문맥의 로컬 저장소에 만들었다.

미완료 13곳이 6+6+1 구간이 되는 것을 확인했다. 위치 확인 전 자동 GPS 요청은 없고, 첫 네이버 차량 경로는 지도앱의 현재 위치를 사용했다. 명시적 합성 GPS 확인 뒤 네이버 앱·카카오 웹·카카오 앱의 모든 구간이 정확한 차량 모드·경유지 순서·목적지를 유지했다. 다음 구간은 이전 도착점에서 이어지고 마지막 한 시설도 포함됐다. 지도 링크 열기 후 저장된 계획·실행 중 계획·기존 방문 완료·합성 작업 연결이 그대로였으며 서버 재시도 큐는 0건이었다.

다른 새 문맥에서는 지도 선택 중 계획 교체·순서·좌표·철거·방문 완료·점검 완료·계정·화면 변경 8종을 시험해 모두 링크 0개로 거절했다. 위치 거부 상태에서도 단일 시설의 네이버 현재 위치 경로가 남았으며 화면 이동 뒤 늦은 GPS가 노선 화면을 복구하거나 정렬 위치를 바꾸지 않았다.

모든 GPS는 합성 callback(3회), 외부 지도 열기는 URL 수집 stub(12회)이었다. 실제 위치를 수집하거나 지도 웹/앱을 열지 않았다. 브라우저 오류·자산 불일치·비조회 HTTP·Firebase SDK·운영서비스·경로 서버 요청·서비스워커 실행은 0건이었다. 외부 호스트는 차단했다.

390/1280px·light/dark의 진입/마지막 구간 화면 8장을 모두 844px 높이의 `#sheet`만 캡처해 독립 시각 검토를 통과했다. 위치 상태·구간 수·방문 순서·이전 구간 출발점·주요 버튼과 가로 넘침을 확인했다. 별도 검토자도 JSON의 앱 11개·시설 대장 해시를 로컬 Git blob과 직접 대조했다.

실제 지도앱 설치/전환·실제 도로 경로/운전 시간·현장 차량 진입·운영 Firebase 로그인/저장·실운영 접수대장은 검증하지 않았다. 서비스워커는 파일 해시와 기존 회귀 검사 범위이며 기존 사용자의 실기기 업데이트를 직접 확인한 결과는 아니다.

## 사용
