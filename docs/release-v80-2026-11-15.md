# v80 v75~v79 독립 검토 수정

앱 버전은 `v80-review-fixes`다. Firestore 규칙·Functions·데이터 형식은 바꾸지 않으며 앱 공개만으로 반영된다.

## 검토 방법

v75~v79는 작성자의 시험만 통과시켜 공개했다. 작성자의 판단을 넘기지 않은 검토자 2명에게 변경 코드와 의도만 주고 결함을 찾게 했다. 받은 지적은 모두 코드와 시험으로 다시 확인한 뒤, 확인된 것만 고쳤다.

## 고친 문제

| 버전 | 문제 | 수정 |
|---|---|---|
| v76 | 시설 화면의 "분전함·회로와 부품 이력" 조회가 한 번 실패하면(연결 끊김 등), 같은 접속 동안 그 시설을 다시 열어도 실패 안내만 보였다. | 실패한 결과는 다시 쓰지 않고, 다음에 열 때 다시 조회한다. |
| v76 | 관리 화면의 새로고침, 나중에 전송된 분전함·회로 저장 뒤에도 시설 화면은 처음 읽은 내용을 계속 보여 관리 화면과 달랐다. | 새로고침(관리 화면 열기 포함)과 대기 중이던 자산 저장의 전송 완료 시 시설별 조회 결과를 버리고 다시 읽는다. |
| v75 | 계획 지도를 연 뒤 방문지 점검이 저장되었거나 계획이 바뀐 경우, "한 칸 앞" 등을 눌러도 아무 일도 없고 지도 번호도 그대로였다. | 바꿀 수 없는 이동이면 현재 계획으로 지도를 갱신하고, 계획이 바뀌었으면 "계획 지도를 다시 열어 주세요"라고 알린다. |
| v75 | 순서 저장이 실패해도 화면의 계획 목록은 바뀐 순서로 남아, 다시 열면 순서가 되돌아갔다. | 저장에 실패하면 원래 순서로 되돌리고 실패를 알린다. |
| v77 | 출동 자료(예: 버전 3)를 받은 뒤 관리자가 작업을 고치고(버전 4) 담당자가 그 작업에 완료 내용을 입력했다면, 약한 신호에서 출동 자료로 열 때 입력의 기준 버전이 3으로 되돌려 저장되었다. 이미 전송 대기 중인 입력이면 빈 완료 양식이 새로 열렸다. | 출동 자료가 저장된 입력보다 오래되었으면 열지 않고, 입력은 저장 대기함·초안에 그대로 있으니 연결된 뒤 다시 열라고 안내한다. |
| v77 | 출동 자료로 연 작업에서 다른 화면에 갔다가 뒤로 돌아오면, 연결이 돌아온 뒤에도 출동 자료 사본을 다시 보여 주었다. | 작업 목록이 여전히 불러오는 중이거나 연결 문제로 실패한 경우에만 출동 자료를 다시 쓰고, 아니면 서버에서 읽는다. |

## 확인했지만 고치지 않은 지적

- **v79 "내 위치"를 Leaflet이 만든 두 번 누름으로 확대**: Leaflet 1.9.4는 같은 `click` 두 번(detail 1)으로 두 번 누름을 만들기도 한다. 그러나 v78/v79가 붙인 `disableClickPropagation`이 버튼에도 같은 두 번 누름 감지를 달아 두 번째 `click`의 전파를 멈추므로, 지도 쪽 감지는 일어나지 않는다. v78/v79 코드를 뺀 상태에서는 확대되고 지금 코드에서는 확대되지 않는 것을 브라우저 시험으로 확인했고, 이 시험을 회귀 시험으로 남겼다.
- **계획을 여러 탭에서 동시에 고칠 때 덮어쓰기**, **출동 자료에서 연 작업의 신고가 공용 목록에 남음**: v75·v77 이전부터 있던 방식이며 이번 변경과 무관해 제외했다.

## 검증

- 새 시험은 모두 수정 전 코드에서 실패하는 것을 확인했다: 시설 조회 재시도·캐시 비우기 2개(`asset-facility-summary`), 지도 순서 변경 결과 전달 1개(`operations-drafts`), 오래된 출동 자료·뒤로 가기 2개(`work-slow-signal`).
- `marker-selection-browser-smoke.cjs`에 Leaflet 방식의 두 번 누름 시험을 추가했다(위 설명).
- Node 691/691, 자산·작업·현장·오프라인·방문계획·지도 브라우저 검사 11종 통과. 실제 휴대폰 확인은 아니다.
