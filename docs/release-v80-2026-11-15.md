# v80 운영 시스템 연계 기본 기간을 한국 시간으로

앱 버전은 `v80-handoff-kst-range`다. Firestore 규칙·Functions·데이터 형식은 바꾸지 않으며 앱 공개만으로 반영된다.

## 발견

v75~v79 검토 수정(PR #63)의 CI 브라우저 검사가 `roadlighting-bridge-browser-smoke.cjs`의 자료 준비 단계에서 두 번 연속 시간 초과로 실패했다. 같은 CI를 `main`에서 돌려도 같은 곳에서 실패해, PR과 무관한 기존 문제로 확인했다. 앞서 통과한 CI는 모두 UTC 15:00(한국 자정) 이전에 실행됐다. GitHub Pages 배포도 같은 브라우저 검사를 거치므로, 그대로 두면 매일 한국 시간 00:00~09:00에는 배포가 막힌다.

## 원인

운영 시스템 연계 화면(`app/roadlighting.js`)의 기본 기간을 **기기의 현지 날짜**(`getFullYear/getMonth/getDate`)로 정하면서, 조회 범위는 **한국 시간**(`+09:00`)으로 계산했다. CI처럼 UTC 기기에서는 UTC 15:00 이후 기본 종료일이 한국 날짜보다 하루 이르게 잡혀, 그날 만든 기록이 범위에서 빠지고 "선택한 기간에 내보낼 기록 자료가 없어요."로 끝났다. 시험 브라우저 시간대를 UTC로 두고 재현했다.

직원 휴대폰은 한국 시간대라 실제로 드러날 일은 드물지만, 두 계산이 서로 다른 시간대를 쓰는 것 자체가 결함이다.

## 수정

- `DGRoadlightingCore.defaultRange(now)`: 한국 시간 기준 이번 달 1일~오늘을 돌려준다. 기기 시간대와 무관하다.
- 연계 화면은 이 값으로 기본 기간을 정한다. `roadlighting-core.js`가 없는 화면에서도 파일이 불러와지도록 빈 기간으로 시작한다(앱은 항상 core를 먼저 불러온다).

## 검증

- 새 Node 시험 `scripts/tests/roadlighting-default-range.test.cjs` 3개(UTC 03:00·15:30, 한국 기준 월 첫날): 수정 전 실패, 수정 후 통과. 실행 시각과 무관하게 고정 시각으로 확인한다.
- 시험 브라우저 시간대 UTC, UTC 15:33에 연계 검사를 다시 실행: 수정 전 기본 종료일 `2026-11-14`·기록 0건으로 실패, 수정 후 `2026-11-15`·기록 포함으로 통과.
- Node 689/689, 운영 시스템 연계를 쓰는 브라우저 검사 6종 통과.
