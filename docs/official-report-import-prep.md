# 운영 신고 파일 반입 준비 (미배포)

이 기능은 담당 부서 협의 전 구현·검증용이다. 실제 운영서비스의 신고 조회·자동 로그인·비공개 API 호출·첨부 다운로드를 하지 않는다. 공개 배포와 운영 저장소 반입도 수행하지 않는다. 공식 업체의 반출 형식·API 계약은 아직 확인되지 않았다.

## 체험에서 확인하기

개발 앱을 localhost 체험 모드에서 열고 관리자 역할을 선택한다. **관리 현황 → 운영 시스템 연계 → 운영 신고 파일 검토**를 연다. 실제 저장소에서는 파일 선택과 반입을 사용할 수 없다.

1. **합성 예제로 확인**하거나 CSV/JSON 준비 양식을 내려받는다. 실제 운영 자료는 담당 부서 협의 후 허용 범위를 확인한다.
2. 파일을 선택한다. UTF-8 CSV 또는 버전 1 JSON, 최대 2MiB·1,000건을 지원한다. 파일 읽기 중 **검토 취소**를 누르면 늦은 결과가 다시 표시되지 않는다.
3. 신규·중복·종결·시설 미연결·시설 중복·내용 충돌을 확인한다. 같은 신고번호의 다른 내용은 모두 제외하고, 운영 시설번호가 유일한 활성 시설에 일치한 신규만 선택한다.
4. **체험 신고함에 가져오기**를 누른다. 선택한 신규만 한 번에 만든다. 재시도·재반입은 기존 신고를 덮지 않는다. 원본 상태가 처리 중이어도 직원 신고의 새 상태는 `접수`다. 기존 보수 작업과 처리 완료 상태를 변경하지 않는다.

원본 파일·이름·연락처·사진·좌표·위치 설명·자유 메모 등 추가 입력은 초안·이력·로그·신고 문서에 저장하지 않는다. 지정한 업무 식별자와 시설번호는 남으므로 결과가 익명화된 자료라는 뜻은 아니다. 파일 파싱에 필요한 원문은 일시적으로 메모리에서 처리하며 안전 삭제를 보장하는 기능은 아니다.

## 준비 양식

| 열 | 의미 | 예 |
|---|---|---|
| `external_report_id` | 운영 신고 식별자 | `SAMPLE-0001` |
| `lamp_id` | 실제 운영 시설번호. 앞자리 0을 보존한다. | `001` |
| `issue` | 정해진 고장 유형 | `off` |
| `received_at` | 시간대가 있는 ISO 시각, KST 날짜 또는 양의 정수 밀리초 | `2026-11-08T10:00:00+09:00` |
| `status` | 원본 상태 | `received` |

`issue`: `off`, `flicker`, `day_on`, `broken`, `leaning`, `exposed_wire`, `other` 또는 앱의 동일한 한국어 유형을 사용한다. `status`: `received`, `processing`, `completed`, `cancelled` 또는 `접수`, `처리중`, `완료`, `취소`다. 완료·취소는 적용 대상에서 제외한다. 날짜만 입력하면 KST 자정으로 해석한다. 잘못된 날짜·시간대 없는 시각·수식 형태 식별자·중복 CSV 열은 거절한다.

CSV는 위의 열 이름을 사용한다. JSON 예시는 다음과 같다. 추가 열은 값·원본 키를 보관하지 않고 제외한 개수만 표시한다.

```json
{
  "schemaVersion": 1,
  "reports": [
    {
      "external_report_id": "SAMPLE-0001",
      "lamp_id": "001",
      "issue": "off",
      "received_at": "2026-11-08T10:00:00+09:00",
      "status": "received"
    }
  ]
}
```

이 양식은 준비 기능의 계약이며 실제 업체 양식과의 호환을 주장하지 않는다. 신고의 안정 ID는 준비 출처와 운영 신고번호로 구분한다. `ext`는 기존 QR 원본 관계용이므로 사용하지 않는다. 기존 신고번호가 이미 있으면 새 신고를 만들지 않는다. 표찰·위치·`p` 접두어로 시설을 추정하지 않는다.

## 실행 제한과 동시 변경

실행기는 관리자·쓰기 권한, actor=`local`, DB mode=`local`, Firebase 없음, 동일 계정·DB·namespace·화면·시설 목록을 요구한다. 운영 환경은 읽기 이전에 거절한다. 적용 직전에 최신 신고·시설로 재검토하고 create-if-absent와 예상 문서 없음 조건을 한 로컬 트랜잭션에 적용한다. 부분 성공이나 기존 덮어쓰기를 하지 않는다.

파일 읽기·검토는 취소할 수 있다. 원자 저장이 시작된 뒤에는 취소할 수 없으며, 계정·화면이 바뀌면 늦은 완료가 새 화면·초안을 지우지 않는다. 저장은 캡처한 원래 체험 DB에만 적용된다. 실서버용 작업이나 저장 대기 큐를 등록하지 않으므로 나중에 운영 서버로 자동 재전송되지 않는다.

## 협의 후 연결 작업

담당 부서와 개인정보 처리 근거·반출 항목·접근 권한·보관·감사 범위를 확인한다. 운영 업체와 공식 파일/API 형식·인증·페이지 나누기·변경/삭제·종결·첨부·중복 정책을 합의한다. 그 결과에 맞는 입력 어댑터와 승인된 운영 실행기·권한 규칙을 별도로 구현·검증한 뒤 배포한다. 현재 로컬 실행기의 차단을 단순히 해제하는 것만으로 운영 연결을 완료하지 않는다.
