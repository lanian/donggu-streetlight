# v65 지도 마커 수정

기능 수정 커밋은 `12d8da3ed8e0043a1cf468cf40e67ab7942485f3`, 검사 동기화 보완을 포함한 배포 커밋은 `951da4b13794279a776a4c45ac10629b071a7a32`다. 앱·서비스 워커 버전은 `v65-markers`이며 [Pages 실행](https://github.com/lanian/donggu-streetlight/actions/runs/42429392953)의 코드·서버/권한 규칙·전체 브라우저 39종과 배포 작업이 모두 성공했다. 공개 화면 확인까지 완료했다.

## 반영 범위

1. 일반 확대 지도에서 화면상 가까운 시설을 숫자로 묶고, 표찰 번호·종류·상태 목록에서 각 시설을 선택한다. 실제 운영 좌표를 옮기지 않고 대표 시설의 좌표를 사용한다. 원형 터치 영역은 44px이며, 같은 위치의 39개 시설을 개별 선택할 수 있다.
2. 상세 카드에서 같은 그룹 목록으로 돌아가거나 시설 상세를 보고 지도에 돌아와도 선택과 지도 위치를 복원한다. 추정 좌표에는 현장 확인 안내를 제공한다. 방문 계획은 동좌표만 묶어 원래 순번·완료·다음 방문지와 경로를 유지한다.
3. 필터 변경 시 카드를 닫고 현재 검색어·내 주변 결과를 갱신한다. 다른 지도·다음 선택·입력·닫기·내 주변 전환이 이전 검색 선택을 취소한다. 예전 DOM의 입력 타이머도 새 지도에 반영하지 않는다.
4. 순찰의 진행 방향 위 모드에서 지도 회전과 자동차 회전을 상쇄한다. 359°→1°도 누적 회전값을 사용한다.
5. 밝기 검토는 모델과 같이 분전함 추정 좌표의 범위 원을 제외하고 그 이유를 안내한다. 추정 시설 자료와 후보·독립 관찰 자체를 삭제하지 않는다.

Firebase·주민 설정, 시설 원본·작업·점검 저장 형식, 규칙·Functions는 변경하지 않았다. v61 유지보수 개발분은 여전히 별도 개발 폴더에 보존하며 새 규칙과 함께 배포해야 한다.

첫 원격 브라우저 실행은 조명 업무 검사에서 실패해 배포하지 않았다. DB 저장 확인 뒤 자동 닫기와 검사 도우미의 전체 닫기가 겹칠 수 있어, 편집 폼의 닫힘과 History 정착까지 확인하도록 검사를 강화했다. 제품 저장 코드나 오류 판정을 우회하지 않았다.

로컬 브라우저 회귀는 실제 앱·Leaflet과 공개 대장 좌표를 사용하지만 Firebase·타일·센서는 격리한다. 실제 운영 직원 인증·주행 중 GPS·나침반·장시간 현장 성능의 증거가 아니다.

## 공개 화면 확인

공개 HTML·SW·직원 앱/CSS·조명 검토·지도 설정/모듈/CSS·PWA·입력 처리·Firebase/주민 설정 총 12개 모두 HTTP 200이고 배포 소스 해시와 일치했다.

실제 VWorld 영상 63건(Satellite 39건, Hybrid 24건)을 정상 이미지로 수신했다. 공개 대장 동좌표 39시설을 숫자 마커에서 열고 `16-1`, `16-39`를 각각 선택했으며 원본 기록이 불변임을 확인했다. 배경 전환 시 위치·확대·시설 표시와 접힌 배경 버튼도 유지됐다. 비영상 응답과 브라우저 오류는 없었다.

공개 자산을 사용한 시험 브라우저에서 필터와 새 지도에 이전 카드가 열리지 않는 것도 확인했고, 진행 방향을 90°로 제어했을 때 순찰 화살표의 화면 각도가 0°(위)임을 확인했다. 실제 영상 확인 이후의 필터·방향 시나리오는 타일과 GPS를 대체했다. 모든 확인은 Firebase 설정만 브라우저 안에서 `null`로 바꾼 독립 체험 환경이며 운영 계정 로그인·운영 자료 쓰기를 하지 않았다.

기존 앱에서는 미전송 기록·초안을 확인한 뒤 **새 버전 적용**을 실행한다.
