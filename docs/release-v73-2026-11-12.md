# v73 유지보수 기능

기존 v61 개발분을 v72 공개 기준에 통합한다. 앱 버전은 `v73-maintenance`이며 새 Firestore 규칙 반영 후 공개한다. 기존 시설·점검·신고·작업 형식을 계속 지원하며 데이터 이전·삭제를 수행하지 않는다.

## 제공 기능

- 배정 수신 확인, 긴급·기한·보류 알림함과 작업 보류/재개. 원래 상태·기한과 작성 중 완료 내용은 유지한다.
- 실제 분전함·회로·시설 연결, 여러 시설의 공동 장애, 시설별 복구와 연결 작업의 검수.
- 명시적 점검 응답·미실시 사유·수치 측정값. 불완전 점검으로 최근 점검일이나 기존 고장 상태를 자동 해제하지 않는다.
- 관리자 정기점검 계획과 회차별 작업 생성. 미완료 작업을 이어가고 재시도 시 중복 생성하지 않는다.
- 부품 교체·제조사/모델·보증·관련 작업 이력. 교체 이력 기록 자체가 재고를 추가 차감하지 않는다.
- 작업·시설·신고 요약·최근 점검·원본 사진·회로 자료를 기기에 준비한다. 준비 시각·범위·누락을 표시하며 이전 준비 자료와 개인정보 제외 원칙을 유지한다.
- 새 기록의 백업과 복원 검증. 서버 복원 호출은 기존 `functionsEnabled:false`와 App Check 설정을 유지해 사전 차단된다.

분전함·회로/시설 이력과 정기점검, 출동 자료는 **관리 현황**에서 연다. 작업 상세에서 배정 확인·보류/재개를 사용하고, 시설의 점검표에서 항목별 응답과 측정값을 기록한다. 정기점검 회차 생성은 앱 안의 명시적 관리자 동작이며 앱이 닫힌 동안의 자동 생성·푸시 발송을 추가하지 않는다.

## 보존과 검증

저장 대기·확인창·전송 응답 중 계정/DB/저장 범위/화면이 바뀌면 이전 점검 작업으로 새 초안을 저장·삭제하지 않는다. 새 사진·메모·측정값, 기존 job ID·날짜·재시도 payload는 유지한다. 규칙은 확인 시각과 확인자, 변경한 보류의 실제 작성자도 검증한다.

로컬 통합 Node 657개, 실제 Node 22 Functions 9개, Firestore 규칙 66개·서버 7개·복원 8개, 전체 Chromium 스크립트 51종을 확인했다. 이후 배포 검사에서 발견한 회로 목록 갱신 경합은 결정적 재현 후 수정하고 자산 브라우저 검사를 다시 통과했다. 모바일/PC·밝음/어두움의 합성 화면 20장을 독립 검토했다. 원격 CI와 실제 서버 규칙·공개 앱 확인은 별도의 배포 근거로 남긴다.

검증은 합성 자료·로컬 체험 저장소·loopback 에뮬레이터다. 실제 직원 계정의 업무 입력·현장 통신 중단·실제 서버 복원·지도앱 전환을 확인한 결과가 아니다. 실제 접수대장 조회는 승인 자료가 없어 계속 미연결이다. Firebase 프로젝트·지도·주민 신고 설정은 변경하지 않는다.
