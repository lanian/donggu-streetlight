# v74 유지보수 결함 수정

공개 v73(`30db7b9`)의 운영 검토에서 찾은 결함을 고친다. 앱 버전은 `v74-maintenance-fixes`다. **Firestore 규칙·Functions·데이터 형식은 바꾸지 않으며** 앱 공개만으로 반영된다. 데이터 이전·삭제는 없다.

## 수정 내용

1. **철거 시설 때문에 정기점검 계획이 멈추던 문제** — 계획 대상 중 한 곳이라도 철거되거나 대장에서 빠지면 회차 생성 전체가 중단됐고, 계획을 수정할 방법도 없었다. 이제 회차 생성 시 관리자에게 해당 시설(최대 5곳 표시)을 알리고, 확인하면 계획에서 빼서 저장한 뒤 회차를 이어 간다. 정리는 일반 계획 저장이라 저장 영수증과 버전으로 누가 언제 뺐는지 남는다. 대상이 모두 사라진 것으로 보이면 대장 조회 실패일 수 있으므로 계획을 비우지 않고 중지를 안내한다.
2. **작업 정보 수정 중 현장 완료 입력이 사라지던 문제** — 담당자가 조치 내용·사진을 입력해 둔 사이 관리자가 기한·우선순위 등을 바꾸면, 다시 열 때 빈 초안이 새 키로 열리고 대기함의 "이어 쓰기"로도 복구되지 않았다. 이제 입력을 최신 작업 버전으로 같은 자리에서 옮기고 확인을 안내한다. 초안은 시작 시점의 자재·측정값을 기준으로 기록해, 담당자가 손대지 않은 값은 관리자의 최신값을 따르고 담당자가 입력한 값은 유지한다. 양쪽이 모두 바꿨으면 입력값을 유지하되 사용 자재 확인을 명시적으로 안내한다. 전송 대기 중인 완료 요청이 있거나, 다른 담당자로 바뀌었거나, 작업이 배정·진행 단계를 벗어났으면 옮기지 않는다. 기기 저장에 실패해도 작업 화면은 열린다.
3. **출동 자료를 받아 둔 기기의 입력 지연** — 기기 보관 목록 조회가 계정의 모든 기록(최대 12MB 출동 자료 포함)을 읽은 뒤 걸렀고, 저장 안 된 입력 확인이 자동 보관마다 13번 실행됐다. 이제 요청한 종류의 키 범위만 읽는다.
4. **검수 대기 작업의 담당자 변경이 권한 오류로 실패하던 문제** — 담당자를 바꾸면 수신 확인·보류를 초기화하는데 서버 규칙은 검수 대기 상태에서 이를 허용하지 않았다. 검수 대기 작업은 완료자가 기록된 상태이므로, 사용 자재와 같이 **보완 요청 후** 담당자를 바꾸도록 수정 화면에서 선택을 잠그고 안내한다. 일괄 수정은 해당 작업만 같은 안내와 함께 건너뛴다.
5. **주민 신고 화면에 연락처가 없던 문제** — 운영서비스 연결 모드에서 전화 안내가 숨겨져, 운영서비스가 열리지 않으면 주민이 연락할 방법이 없었다. `report/config.js`에 `phone`을 설정하면 전화 연결 링크와 연결 실패 안내에 번호를 표시한다. **현재 설정의 `phone`은 비어 있어 담당 부서의 확인된 대표번호 입력이 필요하다.**

6. **알림함이 "배정 미확인"으로 가득 차던 문제** — 수신 확인 기능 이전에 배정된 작업(확인 필드가 아예 없는 작업)은 표시하지 않는다. 이후 다시 배정하면 확인 대상이 된다. 담당자에게는 이미 검수 요청한 작업을 보이지 않고, 관리자는 계속 본다.
7. **연결이 돌아와도 작업 목록이 실패 상태로 남던 문제** — 연결 실패로 목록을 못 읽으면 자동 재조회와 출동 자료를 안내하고, 기기가 다시 온라인이 되면 스스로 다시 불러온다. 권한 오류 등은 자동 재시도하지 않으며, 서버에서 확인하지 않은 캐시 자료는 여전히 목록에 보이지 않는다.
8. **열린 장애가 있는 분전함·회로를 사용 종료하면 장애를 복구 처리할 수 없던 문제** — 사용 종료 저장 전에 장애를 다시 조회해, 열린 장애가 있으면 목록과 함께 거절한다. 트랜잭션에서 목록 조회를 할 수 없어 최신 자료 기준의 사전 확인이다.
9. **운영 안내** — 서버 복원이 꺼져 있어 작업·자산 기록이 든 백업은 웹에서 복원되지 않는다는 점을 운영 안내서에 명시했다. 지도 설정 주석 예시의 실제 키를 자리표시자로 바꿨다.

## 검증

- Node 전체 **676/676**(v73의 657개 + 신규 19개). 정기점검 수정과 완료 초안·목록 범위·담당자 변경 수정은 각각 수정 전 실패를 확인한 뒤 통과시켰다. 정기점검 시험은 실제 명령 처리·로컬 DB와 페이지의 클릭 처리로 저장부터 다음 회차 갱신까지 확인한다.
- 전체 Chromium 브라우저 스크립트 **51/51**(원격 CI와 같은 목록). 이후 수정마다 작업·현장·오프라인·주민 신고·자산·지도 관련 검사를 다시 통과했고, 자산 검사에는 열린 장애가 있는 분전함의 사용 종료 거절 시나리오를 추가했다. 주민 신고 화면에 전화번호 표시·연결 실패 안내·미설정 시 비표시 시나리오 3개를 추가했다.
- 수정 후 독립 검토에서 완료 초안 이전이 관리자의 예정 자재 변경을 덮어쓸 수 있는 문제를 찾아, 재현 시험을 먼저 실패시킨 뒤 수정했다.
- 합성 자료·로컬 저장소 기준이며 실제 직원 계정·현장 기기·iOS Safari 확인은 아니다.

## 남은 확인 사항

- 주민 신고 `phone` 설정(위 5번).
- VWorld 위성 지도 키의 허용 도메인(`lanian.github.io`)·유효기간 확인. `app/map-config.js` 주석 예시에도 같은 키가 들어 있다.
- iOS·인앱 브라우저에서 자동 복사가 막혔을 때 메모가 선택되는지 실기기 확인.
- 실제 복원이 필요해지면 서버 복원 활성화 또는 대량 이전 절차 준비(9번).
- 시설을 처음 열 때 분전함·회로·연결 기록 전체를 읽는다. 연결 자료가 수천 건으로 늘기 전에 시설별 조회로 바꿀 필요가 있다.
- 모바일 인쇄의 PDF 제목 복원 시점, 카카오맵 앱 미설치 시 대체 주소는 실기기 확인 후 수정한다.
