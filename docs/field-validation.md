# 현장 정확도와 오프라인 동작 검증

## 변경 범위

- `app/field.js`에는 센서 좌표 변환, 기울기 안정도, 음성 명령 분기, OSM 링 조립·구멍 판정, 도로 누적 길이 표본화를 둔다. UI와 분리해 실제 수식과 경계 조건을 Node에서 검사한다.
- `app/field-ui.js`는 열린 창의 초점 이동·복원, Tab 순환과 Escape 처리를 맡는다. 사진 편집 중 브라우저 뒤로가기는 편집 창만 닫고 소유 점검 초안을 유지한다.
- 사진·OCR·카메라 후속 처리는 시작한 화면과 작업 번호를 확인한다. 이미 닫히거나 교체된 화면의 늦은 결과가 새 초안을 바꾸지 않는다.
- 휴대전화 기울기는 물리적인 긴 변을 기준으로 계산한다. 알려진 수직 기준에 영점을 맞추고 안정된 측정값만 기록하며, 측정값만으로 시설 불량을 자동 판정하지 않는다.
- AR 방향은 후면 카메라 벡터의 수평 투영이다. 카메라를 거의 위·아래로 향하면 방향을 표시하지 않는다. GPS 이동 방향 보정은 최신 나침반 값과 양호한 GPS 정확도가 있을 때만 허용한다.
- OSM 관계의 조각을 닫힌 링으로 이어서 outer/inner를 구분한다. 불완전한 관계는 제외하고, 구멍 내부를 외곽 영역으로 오인하지 않는다. 캐시 형식은 `ROADS_VER=4`다.
- 도로 길이는 모든 꼭짓점 사이의 실제 누적 거리를 사용한다. 표본 간격보다 짧은 구간과 마지막 잔여 길이도 포함한다. 지도에 표시하는 밝기는 상대 모델 지수이며 조도계 실측 lx나 법적 적합 판정이 아니다.
- 순찰의 행정동 선택은 **진행률 기준 동**이다. 범위 밖의 고장 관찰을 숨기지 않는다. GPS 정확도 25m 이하에서의 근접 통과와 사용자가 누른 직접 점등 확인을 구분한다.

## 업데이트와 저장 중인 작업

`app/pwa.js`의 전역은 `DongguPWA`다. 초안·아웃박스용 `app/offline.js` / `DGOffline`과 별개다.

서비스 워커는 설치 시 무조건 `skipWaiting()`하지 않는다. 사용자가 **새 버전 적용**을 눌렀을 때 저장 중인 작업을 확인하고 대기 워커를 활성화한다. 활성화 뒤에도 다시 확인하며, 다른 탭이 업데이트를 적용했을 때 현재 탭을 자동으로 새로 고치지 않는다.

통합 코드가 제공하는 콜백:

```js
window.DG_HAS_UNSAVED_WORK = async () => boolean;
window.DG_HAS_UNSAVED_WORK_SYNC = () => boolean; // 선택: beforeunload용 메모리 상태
```

비동기 콜백은 미동기화 작업(`DGOffline.jobs()`의 `state !== "synced"`)과 `draft`, `patrol`, `workDraft`, `workCompletion`, `lightingDraft`의 저장 중인 내용을 포함해야 한다. 콜백 오류는 안전하게 업데이트 보류로 처리한다. 네이티브 페이지 종료 경고는 동기 상태만 확인할 수 있으므로 콜백을 생략하더라도 초안의 내구성 저장을 별도로 유지해야 한다.

최종 릴리스에서 새로 추가하는 모든 필수 스크립트는 `sw.js`의 `SHELL_FILES`와 Pages 공개 파일 목록에 함께 추가한다. 한 파일이라도 없으면 설치가 완료되지 않는다. API 응답, 개인 사진, 인증 데이터와 POST 요청은 이 서비스 워커의 공개 캐시에 저장하지 않는다.

## 지도와 오프라인 준비

`app/map-config.js`의 `DONGGU_MAP_PROVIDER` 기본값은 `null`이다. 별도 허가된 지도 제공기관이 없으면 오프라인 배경지도 준비를 완료했다고 표시하지 않는다.

OSM 표준 타일은 서비스 워커가 가로채지 않고 브라우저의 정상 HTTP 캐시를 사용한다. 지역 단위 사전 다운로드·일괄 다운로드 기능은 없다. 별도 제공기관을 설정하려면 이용 허가와 `offlineAllowed: true`가 필요하다. 키가 필요한 제공기관은 공개·도메인 제한 키를 설정해야 하며 서버 비밀 키를 넣지 않는다. 설정된 제공기관도 현재 화면에서 실제 요청한 타일만 제한된 개수와 만료 기간 내 보관한다.

오프라인 상태는 필수 앱 파일, 시설 대장, OCR 엔진·언어 파일을 각각 확인한다. OCR 준비는 한국어·영어 엔진을 실행한 뒤 필수 캐시 파일을 확인하며, 다운로드가 누락되면 준비 완료로 표시하지 않는다. 브라우저가 저장 공간을 회수하면 다시 준비해야 한다.

## 재현 가능한 검증

```sh
node scripts/check.mjs
node scripts/tests/field.test.cjs
node scripts/tests/pwa.test.cjs
```

현장 회귀 31개와 PWA 회귀 8개를 통과했다. 기존 QR 검사에는 출력 가능한 5,467개 대장의 ID 왕복 검증과 중복 표찰 구분이 포함된다. 전체 검사기는 소스 구문, 배포 자산, 5,553개 대장 레코드와 기존 테스트를 함께 확인한다.

실제 브라우저 검사는 외부 요청을 차단한 로컬 서버와 독립 프로필을 사용한다. Playwright와 Chromium 설치 위치를 환경변수로 지정할 수 있다.

```sh
DONGGU_PLAYWRIGHT_MODULE=/path/to/playwright \
DONGGU_CHROMIUM=/path/to/chromium \
node scripts/field-browser-smoke.cjs
```

390×844 화면에서 사진 편집 중 뒤로가기, 초안 소유권, 사진 저장, Tab/Shift+Tab/Escape, 초점 복원, 화면 가로 넘침, 오프라인 새 탭의 대장·QR 부팅, OCR 미준비 안내, 작성 중 초안이 있는 업데이트 활성화 차단을 확인했다. 검사 중 처리되지 않은 브라우저 오류는 없었다. 운영 데이터베이스에는 연결하거나 쓰지 않았다.

## 실제 장비에서 남은 확인

자동 검사는 좌표 변환·거리 계산·상태 전이의 정확성을 확인한다. 휴대전화 센서의 절대 정확도, 금속·차량의 자기장 간섭, 도심 GPS 반사, 장갑 사용, 야간 표찰 OCR 정확도는 실제 장비로 확인해야 한다. Android, iOS와 기본 화면이 가로인 태블릿에서 알려진 수직 기준과 방위를 비교한다. 현장의 현재 OSM 경계 데이터와 실제 도로·소유권도 대조한다.

브라우저 검사는 OCR 파일이 없는 상태를 미준비로 표시하는지 확인했다. 전체 OCR 엔진·한국어 언어 파일을 내려받은 후 네트워크를 끊고 실제 사진을 인식하는 장비 검수는 별도로 수행한다.

수식과 타일 정책의 근거:

- [W3C Device Orientation and Motion](https://www.w3.org/TR/orientation-event/)
- [OpenStreetMap Tile Usage Policy](https://operations.osmfoundation.org/policies/tiles/)
