# 주민 신고 분리 계획

작성 2026-10-13 · 상태: 1단계 구현 완료, 2단계 설정 대기

## 결정
- 점검자와 관리자는 **같은 앱**(index.html)을 쓴다. 관리자 PC는 인터넷망 접근이 가능하므로 아티팩트·GitHub Pages 주소를 그대로 쓴다.
- 주민(신고자)은 **별도 페이지**(`report/`)로 분리한다. 주민은 등 목록·점검자·사진·순찰 경로를 볼 수 없고, 직원 앱에 참여자 권한을 줄 필요가 없다.

## 구조
```
표찰 QR ──▶ report/?c=표찰번호 (공개, 로그인 없음, 신고만)
                 │  1단계: 문자/이메일로 보내기 → 담당자가 직원 앱 '신고함'에 기록
                 │  2단계: Firestore(create-only)로 자동 접수 → 직원 앱이 읽어 옴
                 ▼
직원 앱 (점검자·관리자) ── 신고함: 접수 경로·등 연결·상태(접수→처리중→완료)·CSV
```

## 1단계 — 지금 되는 것 (백엔드 없음)
1. `report/index.html` — 등 번호(QR로 자동 입력)·문제 유형·내용·사진 1장(≤150KB)·현재 위치(선택)·연락처(선택, 보관 동의)·접수번호 발급. 개인정보 안내 포함.
2. 보내기: `report/config.js`의 `sms`/`mail`을 채우면 문자·이메일 앱이 열리고, 안 열리면 내용 복사. 사진은 메시지에 직접 첨부.
3. 직원 앱 **신고함**(관리 메뉴): 전화·문자·이메일·방문·QR 신고를 담당자가 기록. 등 번호를 넣으면 대장 등과 연결되고 등 상세에 "신고 N건"이 뜬다. 상태 변경, 미완료만 보기, 신고 CSV.
4. 직원 앱 **QR 라벨**(관리자): 표찰별 QR(신고 페이지 주소+번호) 라벨 인쇄. 점검자가 같은 QR을 앱으로 찍으면 그 등이 열린다(주소 QR 해석).
5. 주민 탭은 꺼진 채로 둔다(`FEATURES.reports=false`).

## 2단계 — 자동 접수 (설정만 하면 됨)
1. Firebase 프로젝트 생성 → Firestore → `report/firestore.rules` 적용(누구나 create만, 읽기는 직원 도메인 계정만). 직원 도메인을 규칙 안에서 바꾼다.
2. `report/config.js`: `backend:"firestore"`, `firestore.projectId`, `firestore.apiKey` 입력. 페이지는 Firestore REST로 바로 저장한다(SDK 없음).
3. 직원 앱 쪽 읽기는 직원 Google 로그인이 필요하므로 **백엔드 교체(아티팩트 DB → Firestore)** 와 함께 한다. 이때 역할(관리자·점검자)도 서버 규칙으로 강제된다.

## 운영 안내
- QR 라벨을 붙일 때 `REPORT_URL`(index.html 상단 상수)이 실제 배포 주소인지 확인한다.
- 연락처는 처리 안내 후 지운다(신고함에서 완료 처리 시 담당자가 삭제). 보관 기간 안내는 `privacyDays`.
- 사진 안내문: 얼굴·차량 번호판이 나오지 않게.
