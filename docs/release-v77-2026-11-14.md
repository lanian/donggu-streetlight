# v77 약한 신호에서 출동 자료 바로 보기

앱 버전은 `v77-slow-signal-field-kit`다. **Firestore 규칙·Functions·데이터 형식은 바꾸지 않으며** 앱 공개만으로 반영된다.

## 문제

- 작업 목록은 서버 조회가 끝나야 표시된다. 앱에는 별도 대기 한도가 없어, 신호가 약하면 "불러오는 중…"이 오래 이어지거나 Firestore 연결 제한 시간 뒤 실패했다.
- 실패하면 "관리 현황의 출동 자료에서 볼 수 있어요"라는 안내만 있어 직원이 다른 화면으로 가서 찾아야 했다.
- 출동 자료에서 작업을 열어도 먼저 작업 목록 조회가 끝나기를 기다린 뒤 서버에서 작업을 다시 읽었다. 신호가 약하면 같은 대기가 두 번 반복됐다.

## 수정 내용

1. 작업 목록이 연결 문제로 실패하거나, 목록 조회가 **8초** 넘게 끝나지 않으면 작업 화면에 **"출동 자료 · 받은 시각"** 묶음을 표시한다. 이 계정이 받아 둔 작업만 보이고, 서버 목록이 아니며 받은 뒤의 변경은 반영되지 않는다고 함께 적는다.
2. 느린 경우 서버 조회는 그대로 이어진다. 목록이 도착하면 안내는 사라지고 평소 목록으로 바뀐다. 이미 목록이 보이는 상태의 새로고침에는 안내를 띄우지 않는다.
3. 이 묶음에서 연 작업은 목록 조회를 기다리지 않고, 작업·신고를 출동 자료 사본에서 바로 읽는다. 상세 화면에는 기존 "출동 준비자료" 안내가 표시된다. 완료·보류 저장은 기존처럼 전송 대기함을 거쳐 서버에서 버전을 다시 확인한다. 등록 자재 목록은 이 경로에서 비어 있을 수 있으며, 자재는 직접 입력할 수 있다.
4. 받아 둔 자료가 없으면 출동 전에 출동 자료를 준비하는 방법을 안내한다. 권한 오류 등 연결 문제가 아닌 실패에는 표시하지 않는다.

## 고려한 다른 방법

- **기기 캐시를 목록에 섞기**: 다른 직원이 바꾼 내용이 최신처럼 보일 수 있어 제외했다. 서버에서 확인하지 않은 자료를 목록에 섞지 않는다는 기존 원칙을 유지한다.
- **일정 시간 뒤 서버 조회 중단**: 느리지만 결국 도착할 결과를 버리게 되어 제외했다.

## 검증

- 새 Node 시험 `scripts/tests/work-slow-signal.test.cjs` 4개: 8초 뒤 안내와 출동 자료 표시, 연결 실패 시 표시, 자료가 없을 때 안내, 출동 자료에서 연 작업이 서버를 읽지 않고 열림. 수정 전 코드에서 4개 모두 실패하는 것을 확인했다(마지막 시험은 목록 조회 대기로 시간 초과).
- `scripts/inspection-field-kit-v61-browser-smoke.cjs`에 실제 Chromium 시나리오 추가: 출동 자료를 받은 뒤 연결이 끊긴 상태에서 작업 목록이 실패하면, 출동 자료 묶음이 보이고 거기서 작업 상세가 열린다. 수정 전 코드에서 실패하는 것을 확인했다.
- 합성 자료·로컬 저장소 기준이며, 실제 약한 신호 환경·현장 기기 확인은 아니다.
