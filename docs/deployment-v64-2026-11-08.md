# v64 지도 배경 선택창 개선

배포 커밋은 `848f50d7c75b08fdba10cc2876e051706086b505`이며 앱·서비스 워커 버전은 모두 `v64-map-control`이다. [GitHub Pages 실행](https://github.com/lanian/donggu-streetlight/actions/runs/42388216293)의 앱·서버/권한 규칙·브라우저·배포 작업이 모두 성공했고, 공개 화면까지 확인했다.

## 변경

항상 표시하던 180px 선택창을 64×44 크기의 **배경** 버튼으로 접었다. 버튼을 누를 때만 왼쪽에 선택창을 표시한다. 선택·Escape 후 버튼으로 포커스를 돌리고, 바깥 클릭이나 지도 밖 입력으로 이동하면 접는다. 지도 캔버스의 첫 바깥 클릭은 닫기에만 사용해 시설 좌표·경계점 편집을 막는다. 위치 찾기 등 기존 버튼·링크는 정상 실행된다.

오류 안내는 작은 경고 표시, 버튼 설명과 접근성 상태 안내로 유지하며 펼친 창에서 사유를 읽을 수 있다. 지도·선택창을 제거하면 문서 클릭 처리도 해제하고, 이전 선택창의 늦은 이벤트는 무시한다. 순찰에서는 회전판 밖의 컨트롤 배치를 유지한다. Firebase 설정·키·규칙·서버·업무 저장 형식은 바꾸지 않았다.

## 로컬 검증

- 기존 구현에서 접힌 토글이 없는 실패(`0 !== 1`)를 먼저 확인했다.
- 배포 작업 공간 `E:\Projects\streetlight-release-v63-20261108`: Node 406/406 통과.
- 별도 v61 개발분을 보존하는 `E:\Projects\streetlight`: Node 494/494 통과.
- 두 작업 공간의 지도 브라우저 검사 7개 그룹 통과. 초기 접힘, 열기·선택·Escape·포커스, 오류 복귀, 첫 바깥 클릭의 편집 보호와 후속 클릭의 정상 편집, 기존 위치 버튼·링크, 재시작·늦은 이벤트·제거를 확인했다.
- 320/390/1440 화면에서 펼친 창 전체 경계와 위치 버튼 겹침, 320/390의 회전 순찰에서 따라가기·방향 버튼과의 겹침을 확인했다.
- 구역 편집·모달·순찰 지도·PC 위치 버튼 기존 브라우저 4종 통과.
- 독립 코드 검토에서 중요한 문제를 발견하지 못했다.

위 브라우저 회귀는 실제 앱·Leaflet을 사용하되 타일·키와 외부 네트워크를 합성 자료로 대체한다. 운영 직원 인증·현장 장비를 확인한 결과가 아니다.

## 공개 반영 확인

GitHub의 전체 브라우저 38종과 코드·서버/권한 규칙 검사가 성공한 커밋이 게시됐다. 공개 HTML·SW·직원 앱·지도 설정/모듈/CSS·PWA·입력 처리·Firebase/주민 설정 10개 모두 HTTP 200이며 배포 작업 공간의 소스 해시와 일치했다.

게시 자산을 사용하는 독립 브라우저에서 실제 VWorld 항공사진 30건·도로명 15건을 정상 이미지로 받았다. 두 영상 모드에서 지도 위치·확대·시설 표시를 유지하고 선택창이 64×44 버튼으로 접히는 것도 확인했다. 비영상 응답·브라우저 오류는 없었다. 이 확인은 브라우저에서 Firebase 설정만 `null`로 대체한 체험 모드이며 운영 계정 로그인이나 자료 쓰기를 하지 않았다.

기존 앱에서는 미전송 기록과 초안을 확인한 뒤 **새 버전 적용**을 실행한다.
