# 운영 시스템 자료 연계

이 앱은 비공식 현장 보조 도구다. `gjd.roadlighting.kr`의 운영 대장을 참고하여 점검·사진을 정리하고 담당자가 운영 사이트에 등록할 자료를 만든다. 공식 API와 업로드 양식은 확인되지 않았으므로 ZIP을 운영 사이트에 바로 업로드할 수 있다고 가정하지 않는다. 파일을 준비하거나 다운로드해도 민원 접수·보수 등록·검수가 자동 완료되지는 않는다.

## 사용하는 순서

관리자로 로그인한 뒤 **관리 현황 → 운영 시스템 연계**를 연다. 휴대폰에서는 관리 현황의 **PC 업무**에 있다.

1. **운영 대장 가져오기**에서 운영 시스템의 `getPoint.json` 원본 또는 변환한 대장 JSON을 선택한다. 신규·변경·누락과 현장 수정 충돌을 확인하고 적용한다. 실제 사용 중인 서비스가 다른 반출 양식만 제공한다면 먼저 그 양식을 확인해야 한다.
2. 기간·동·자료 종류를 선택하고 **선택한 자료 조회**를 누른다. 정상 점검도 포함한다. 보수는 기간 중 생성·변경·완료 요청·검수 또는 처리 이력이 있는 작업이다. 동을 선택한 순찰은 그 동이 포함된 세션 전체이므로 거리·누적 통과를 해당 동의 실적으로 나누어 해석하지 않는다.
3. 건수와 자료 출처를 확인하고 **전달 묶음 준비 → ZIP 파일 내보내기**를 누른다. 사진 원본을 확인하지 못하면 대체·누락 여부가 표시된다. 연락처 필드는 기본 제외이며 메모·설명·사진의 자유 입력 내용까지 익명화한 자료는 아니다.
4. 담당자가 기존 운영 절차에 따라 내용을 검토·등록한다. 공식 반입 양식이 확인되기 전에는 CSV·사진을 검토용 자료로 사용한다. **운영 사이트 열기**는 로그인·신고·수정을 자동 실행하지 않는다.
5. 돌아와서 **이 기기의 연계 이력**에서 묶음과 개별 기록을 고른다. 실제 운영 화면에서 확인한 등록번호를 입력하고 **확인 내용 기록**을 누른다. 미반영·실패 상태는 사유와 함께 기록한다.

## 대장 보존 규칙

- 연결 기준은 `lamp_id → lampId`, 내부 시설 ID는 `p + lamp_id`다. 표찰 번호·가까운 좌표만으로 서로 다른 시설을 자동 연결하지 않는다.
- 현재 대장은 운영 자료와 다른 공개대장을 합친 자료다. 운영 자료는 해당 출처의 시설만 비교하며 다른 출처 시설은 유지한다.
- 원본이 제공하지 않은 필드와 현장 수정값을 보존한다. 명시적으로 제공된 null과 미제공은 구별한다. 현장 수정 보존을 끌 때만 미리보기에 표시된 충돌 값을 검토해 교체한다.
- 운영 자료에 없는 시설은 자동 철거하지 않는다. 임의로 입력 요소를 변경해도 운영 자료의 누락 철거는 실행하지 않는다.
- 잘못된 ID·중복·출처 간 ID 충돌·잘못된 좌표·선언된 불완전 자료는 거부한다. 새 시설은 종류가 필요하다. 이미 연결된 점검·사진·보수 기록과 현재 상태는 대장 갱신으로 초기화하지 않는다.

## ZIP 구성

| 파일 | 용도 |
|---|---|
| `manifest.json` | 비공식 여부, 대상·기간·출처, 묶음 ID·내용 해시, 파일별 SHA-256, 기록·사진 연결 |
| `records.json` | 원문을 보존한 형식별 전달 기록. CSV 수식 중립화로 표시가 달라진 값의 원문도 이 파일에 남는다. |
| `inspections.csv`, `reports.csv` | 정상 포함 점검과 신고 자료 |
| `works.csv`, `work-events.csv` | 현재 작업 정보와 기간 내 처리 이력·비용 증감 |
| `patrols.csv` | 순찰 세션·누적 통과·점검 표시·경로 |
| `photos.csv`, `photos/` | 원본/미리보기 대체/누락/제외 구분과 기록별 사진 관계. 동일 사진 바이트는 한 파일로 저장한다. |
| `README.txt` | 대상 시스템 등록 전 확인 사항과 파일 해석 방법 |

개별 기록에는 자료 종류·내부 기록 ID·시설 ID·운영 시설번호·원본 시각·버전·내용 해시가 있다. 시설번호 연결이 없으면 표시하며, 같은 운영 시설번호가 여러 시설에 연결된 경우 내보내기를 중단한다. 잘못된 시설·작업에 연결된 사진은 포함하지 않는다. 작업의 `completed`는 **검수 대기**, `verified`는 **검수 완료**로 구분한다.

같은 범위와 실제 전달 내용이면 생성 시각이 달라도 같은 묶음 ID를 사용한다. 생성 시각 등 메타데이터가 달라 ZIP 전체 파일의 해시는 달라질 수 있다. 원문·사진·공유 범위가 달라지면 다른 묶음이 된다. 이전 등록 확인을 변경된 자료에 자동 전파하지 않는다.

ZIP은 UTF-8·무압축이며 최대 200MiB다. 용량을 넘으면 기간을 나누거나 사진 포함을 해제한다. 자료를 일정 건수로 조용히 자르지 않는다. 서버 자료 조회가 실패하면 이전 자료를 새 조회 결과처럼 내보내지 않는다. 화면·계정·저장소·권한·선택 조건이 바뀌면 진행 중인 준비를 취소한다.

## 등록 확인 이력과 한계

등록 확인은 운영 시스템을 확인한 사용자의 기록이며 서버 응답을 검증한 전자 영수증이 아니다. 입력해도 원래 점검·작업·재고·검수 상태를 변경하지 않는다.

이력은 기존 `DGOffline`의 계정·저장소별 기기 영역에 보관한다. 다른 기기·브라우저로 자동 공유되지 않으며, 임시 저장 모드에서는 창을 닫으면 사라진다. 다른 탭에서 이력을 변경했으면 충돌을 알리고 최신 이력과 다시 비교한다. 실제 운영 시스템의 중복 등록 방지는 해당 시스템의 확인 절차가 필요하다.

공식 API가 준비되면 읽기 전용 조회부터 검증한 뒤 등록번호 응답·첨부 규격·권한·충돌 정책을 확인하여 서버 중계로 확장할 수 있다. 현재 버전은 업체 비밀번호·API 비밀키·자동 로그인·자동 접수 요청을 추가하지 않는다.
